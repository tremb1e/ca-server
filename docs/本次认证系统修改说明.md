# 本次认证系统修改说明

日期：2026-05-29

本文档记录本轮对持续认证服务端的主要改动、配置项、测试证据与部署验证结果。

## 1. 修改目标覆盖

本轮修改围绕以下目标完成：

- 用户数据集生成从固定体量改为配置驱动的动态阈值，默认阈值 300MB。
- 数据切分按 75% / 12.5% / 12.5% 分配训练、验证、测试数据。
- 使用 HMOG 填充验证集和测试集时，让真实用户数据与 HMOG 数据量约为 1:1。
- HMOG 验证集使用排序靠前用户，测试集使用排序靠后用户，每侧至少 10 个用户，并以每个用户 24 个 session 为候选来源。
- 多用户数据处理从逐用户串行改为多进程并行；HMOG 加载也改为按 subject 并发加载。
- VQGAN 输入从旧 12 轴格式改为 `(1, 9, T)`，不再使用三个模长通道。
- 训练最大 epoch 改为 50，早停改为验证集性能连续 3 次不提升即停止。
- 训练、策略搜索和推理增加详细日志和结果字段，方便阈值与策略搜索。
- 保留 y-of-x 投票机制，新增并默认使用 EMA 决策策略。
- 将 `policy_search` 与线上认证策略打通，训练后默认写入线上消费的 `models/<user>/best_lock_policy.json`。
- 修复模型就绪检查遗漏 `processed_data/z-score/<user>/scaler.json` 的问题。
- 适配 Kunpeng 920 + Ascend 910B 8 卡 NPU 环境，并在多用户训练时利用可见 NPU 设备池。
- 将关键参数集中到 `ca_config.toml` 和 `deploy/config/ca_config.toml`，并补充中文注释。
- 补充项目文档、训练文档和本修改说明。
- 停止旧容器、删除旧服务镜像标签，重新构建并运行新镜像，完成健康检查和 NPU 可见性验证。

## 2. 数据集生成

配置入口：

- `ca_config.toml`
- `deploy/config/ca_config.toml`
- `src/ca_config.py`

核心实现：

- `src/processing/pipeline.py`

主要行为：

- `[processing].min_total_mb = 300`：默认触发阈值为 300MB。
- `[processing].target_total_mb = 300`：默认用于处理的数据目标为 300MB。
- `[processing].train_ratio = 0.75`
- `[processing].val_ratio = 0.125`
- `[processing].test_ratio = 0.125`

若系统设置阈值记为 `100x`，实际分配即为：

- 训练集：`75x`
- 验证集：`12.5x`
- 测试集：`12.5x`

HMOG 填充策略：

- 验证集使用排序靠前的 HMOG 用户。
- 测试集使用排序靠后的 HMOG 用户。
- 每侧默认至少 10 个 HMOG 用户。
- 每个 HMOG 用户默认以 24 个 session 为候选来源。
- `[processing].hmog_balance_ratio = 1.0`，即验证/测试集中真实用户数据与 HMOG 数据约为 1:1。
- `hmog_max_rows_per_subject` 和 `hmog_max_rows_total` 默认 0，生产运行不限制；smoke test 可临时设置上限以节省时间和磁盘。

并发改动：

- `process_all_users()` 使用 `ProcessPoolExecutor` 做用户级并行。
- 单个用户内部的 session 处理仍受 `[processing].workers` 控制。
- 多用户并发时会按用户级并发自动分配子任务 worker，避免所有用户同时抢满 CPU。
- HMOG subject 加载改为线程并发，避免每个目标用户串行重复加载同一批 HMOG。

## 3. VQGAN 9 轴输入

涉及文件：

- `ca_train/hmog_data.py`
- `src/authentication/vqgan_inference.py`
- `src/training/runner.py`
- `ca_train/hmog_vqgan_experiment.py`
- `ca_train/hmog_token_auth_inference.py`
- `ca_train/hmog_vqgan_token_transformer_experiment.py`
- `ca_train/vqgan.py`
- `ca_train/encoder.py`
- `ca_train/decoder.py`
- `ca_train/hmog_tokenizer.py`
- 相关测试 fixture

当前输入格式：

```text
(batch, 1, 9, T)
```

9 个通道：

```text
acc_x, acc_y, acc_z,
gyr_x, gyr_y, gyr_z,
mag_x, mag_y, mag_z
```

已去除：

```text
acc_magnitude, gyr_magnitude, mag_magnitude
```

线上保护：

- `vqgan_inference.py` 会拒绝 `input_height != 9` 的模型配置。
- `has_trained_model()` 和管理快照会把旧 12 轴模型判定为不可用。
- 因输入分布变化，全部用户模型需要重新训练，阈值需要由新的 `policy_search` 重新标定。

## 4. 训练、早停与日志

配置入口：

- `[training].max_epochs = 50`
- `[training].early_stop_patience = 3`
- `[training].batch_size = 128`
- `[training].device = "auto"`
- `[training].max_parallel_train = 8`
- `[training].run_policy_search = true`

核心实现：

- `src/training/manager.py`
- `src/training/runner.py`
- `ca_train/hmog_vqgan_experiment.py`

训练行为：

- 默认最多训练 50 epoch。
- 验证集 AUC 连续 3 次不提升时早停。
- 每个 epoch 记录 train / val / test 关键指标。
- 训练结束恢复最佳 epoch 权重。
- 训练完成后默认调用 `policy_search`，将验证集上选出的策略写入模型目录。

NPU 并行：

- `src/utils/accelerator.py` 支持 `auto / npu:<id> / cuda:<id> / cpu`。
- `device=auto` 优先选择 NPU，其次 CUDA，最后 CPU。
- 多用户训练任务按 `device_pool()` 分配到可见设备。
- 在 8 卡 Ascend 910B 环境中，默认设备池为 `npu:0` 到 `npu:7`。

## 5. 策略搜索与线上打通

涉及文件：

- `src/policy_search/runner.py`
- `src/policy_search/cli.py`
- `src/authentication/runner.py`
- `src/authentication/manager.py`
- `src/utils/reject_trackers.py`

当前策略：

- 默认 `decision_strategy = "ema"`。
- 保留 `vote`，即 y-of-x 投票机制。
- 保留 `k`，兼容旧的连续 K 次拒绝。

EMA 策略：

- 对 VQGAN 原始窗口分数做指数滑动平均。
- `ema_alpha` 默认来自配置，最终每用户可由 `policy_search` 在验证集上选择。
- 目标是在不明显牺牲攻击检测的前提下降低真实用户短时波动造成的 FRR。

policy_search 输出：

```text
models/<user>/best_lock_policy.json
models/<user>/policy_search/grid_results_vqgan_only.csv
models/<user>/policy_search/pareto_frontier_vqgan_only.csv
models/<user>/policy_search/best_lock_policy_vqgan_only.json
```

线上消费：

- 在线认证优先读取 `models/<user>/best_lock_policy.json`。
- 读取 `decision_strategy`、`threshold`、`ema_alpha`、`vote_window_size`、`vote_min_rejects` 等字段。
- 当前线上打分为 VQGAN-only，因此默认 `policy_search_auth_method = "vqgan-only"`，避免离线 transformer 分数与线上 VQGAN 分数错位。

离线认证结果字段：

- `score`
- `ema_score`
- `decision_strategy`
- `raw_accept`
- `decision_accept`
- `accept`
- `interrupt`
- `consecutive_rejects`
- `vote_recent_windows`
- `vote_recent_rejects`

## 6. 模型就绪检查修复

涉及文件：

- `src/authentication/manager.py`
- `src/management/snapshot.py`
- `tests/unit/test_management_api.py`

修复前风险：

- 会话只检查 policy、checkpoint、config。
- 如果缺失 `processed_data/z-score/<user>/scaler.json`，`StartAuthentication` 可能接受会话，但后续推理无结果。

修复后要求：

- `best_lock_policy.json` 可读。
- `vqgan_checkpoint` 存在。
- `vqgan_config` 存在且 `input_height == 9`。
- `processed_data/z-score/<user>/scaler.json` 存在且为可解析 JSON。

管理快照也会显示 scaler 文件状态，并把 scaler 纳入模型 ready 判断。

## 7. 配置参数说明

`[processing]`：

- `min_total_mb`：触发预处理和训练的原始数据阈值，默认 300MB。
- `target_total_mb`：实际选择处理的数据量目标，默认 300MB。
- `train_ratio / val_ratio / test_ratio`：真实用户数据切分比例。
- `workers`：单用户内部处理 worker 数。
- `process_user_workers`：多用户处理并发数。
- `hmog_val_subject_count`：验证集使用的 HMOG 用户数。
- `hmog_test_subject_count`：测试集使用的 HMOG 用户数。
- `hmog_min_subject_count`：每侧 HMOG 用户数下限。
- `hmog_session_count`：每个 HMOG 用户候选 session 数，默认 24。
- `hmog_balance_ratio`：HMOG 与真实用户数据体量比例，默认 1.0。
- `hmog_max_rows_per_subject / hmog_max_rows_total`：HMOG 行数上限，默认 0 表示不限。

`[windows]`：

- `sizes`：窗口长度列表，当前默认 `[0.2]`。
- `overlap`：滑窗重叠率，默认 0.5。
- `sampling_rate_hz`：重采样频率，默认 100Hz。

`[auth]`：

- `max_decision_time_sec`：期望首次打断决策时间上限。
- `decision_strategy`：`ema`、`vote` 或 `k`。
- `vote_window_size / vote_min_rejects`：y-of-x 投票参数。
- `ema_alpha`：EMA 默认平滑系数。
- `ema_alpha_candidates`：policy_search 的 EMA 候选值。
- `target_window_frr`：窗口级 FRR 约束。
- `max_genuine_first_interrupt_p`：真实用户在目标时间内被误打断概率约束，可选。
- `policy_search_auth_method`：默认 `vqgan-only`。

`[training]`：

- `max_epochs`：最大训练轮数，默认 50。
- `early_stop_patience`：早停耐心值，默认 3。
- `batch_size`：训练 batch size。
- `device`：默认 `auto`。
- `max_parallel_train`：最大并行训练任务/设备数，默认 8。
- `run_policy_search`：训练结束后是否自动运行策略搜索。

## 11. 注意事项

- 旧 12 轴 checkpoint 与旧阈值不能继续作为线上模型使用。
- 新用户或已有用户上线前必须重新训练并重新运行 `policy_search`。
- 若在非 Ascend 机器上运行，`device=auto` 会回退到 CUDA 或 CPU。
- 本轮用户数据烟测为了快速完成使用了较小数据阈值和 HMOG 行数上限，不能代表完整生产训练性能。
- 生产环境建议保留 `INSTALL_TORCH_NPU=1`，并确保宿主机 Ascend driver/toolkit 与容器挂载路径一致。
