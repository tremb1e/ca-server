# 2026-06-29 本轮修改

日期：2026-06-29

本轮聚焦“VQGAN 输入瘦身、策略发布与上线校验加固、认证结果尺度拆分，以及若干训练死锁/设备 ID 解析缺陷修复”。本轮改动与 2026-05-29 之前的 9 轴模型、旧策略文件不兼容，需重新生成窗口数据、重新训练 VQGAN、重新跑 `policy_search`。

## A. VQGAN 输入由 9 轴改为 6 轴（移除磁力计）

- 模型输入由 `(1, 9, T)` 改为 `(1, 6, T)`；6 行 = 加速度计 `acc_x/y/z` + 陀螺仪 `gyr_x/y/z`，不再使用磁力计 `mag_x/y/z`。
- 模型 config 的 `input_height` 由 9 改为 6（`image_channels` 仍为 1）。
- 数据处理 / 数据集生成：窗口 CSV 的传感器列与 z-score scaler 现为 6 列（`FEATURE_COLUMNS` 去掉 `mag`）；数据重采样不再要求磁力计存在。
- 兼容性：所有此前的 9 轴模型 / scaler / 策略均不兼容，必须重新生成窗口数据、重新训练 VQGAN、重新跑 `policy_search`。
- 涉及处：`ca_train/hmog_data.py`、`ca_train/vqgan` 的 encoder/decoder（`input_height` 默认值）、`src/processing/pipeline.py`、`src/processing/scaler.py`、`src/authentication/vqgan_inference.py`、`src/training/runner.py`(`_vqgan_config`)；各处 `input_height` 校验由 `!= 9` 改为 `!= 6`。

## B. 重构策略发布流程

- 训练阶段不再写正式 `best_lock_policy.json`，改写 `training_fallback_policy.json`，并标记：
  - `policy_status = "training_fallback"`
  - `policy_search_completed = false`
  - `score_metric = "mse"`
  - `score_scale = "negative_reconstruction_error"`
  - `threshold_strategy = "training_val_genuine_threshold"`
- `policy_search` 成功后“原子写入”（先写 `.tmp`，再 `os.replace`）`best_lock_policy.json`，新增字段：
  - `policy_search_completed = true`
  - `policy_status = "ready"`
  - `score_metric = "mse"`
  - `score_scale = "negative_reconstruction_error"`
  - 并落盘 `genuine_score_stats`：来源为 val 上真实用户分数统计，含 `count / min / max / mean / std` 以及 `quantiles{0.001, 0.01, 0.05, 0.5, 0.95, 0.99, 0.999}`。
- 认证启动仅接受 `policy_status = "ready"` 且 `policy_search_completed = true` 的正式策略；新增配置开关 `auth.allow_training_fallback_policy`（默认 `false`），开启后允许在缺少正式策略时显式回退到 `training_fallback_policy.json`（降级运行）。
- 旧策略（无 `policy_status` 字段）向后兼容：
  - 含 `grid_search` 或 `threshold_strategy = "interrupt_window_frr"` 的旧策略推断为 `ready`；
  - 文件名为 `training_fallback_policy.json` 的推断为 `training_fallback`；
  - 其余裸旧策略推断为 `legacy`（不就绪）。

## C. 加固 check_trained_model（模型上线校验）

- 阈值必须为有限值：拒绝 `inf` / `nan` / `sys.float_info.max` 及 `|阈值| >= 1e6` 等异常值。
- 策略必须包含 `threshold_strategy`、`decision_strategy`、`score_metric`、`score_scale` 四个字段。
- 校验 checkpoint / scaler / config / policy 的指纹（sha256 取前 1MB）与 mtime；会话启动时把校验详情写入 `inference/<device>/<session>/model_validation.json`。
- 校验阈值落在训练 / 验证集 genuine 分数分位范围附近（带 margin），明显越界则拒绝上线。
- `has_trained_model` 现委托 `check_trained_model`；gRPC `StartAuthentication` 调用 `check_trained_model` 取得 `(是否就绪, 原因)`。

## D. 拆分认证结果字段（避免尺度混读）

- 迟滞 / EMA 决策结果同时写出三套尺度：
  - `raw_score` / `raw_threshold`：原始分数尺度；
  - `ema_score` / `ema_threshold`：EMA 尺度；
  - `display_score` / `display_threshold`：0~1 可视化尺度。
- 返回 payload 与管理接口均带 `result_stage`（当前恒为 `"primary"`）；管理结果（`/auth/results` 与 `/auth/results/latest`）默认按 stage 分组返回 `by_stage` 字段。
- 旧字段 `score` / `threshold` / `normalized_score` 保留为兼容字段；管理结果读取还会把历史记录的 `decision_score` / `decision_threshold` / `decision_accept` 归一映射到 `score` / `threshold` / `accept`。

## E. 修复模型不可用时训练状态死锁

- 当某用户没有可用模型（从未训练 / 训练中断 / 已完成但校验不通过）时，App 触发 `StartAuthentication` 会以 `force=True` 强制（重）训练；`force` 触发会绕过节流与“持久化 `in_progress` 但无存活任务”的死锁判定。
- window sweep 跑完但没有产出认证可接受的正式策略时，会抛出 `PolicySearchIncompleteError`，训练状态记为 `failed`（可被再次触发重训），不会假装训练成功。

## F. 修复横杠开头设备 ID 训练失败

- 形如以 `-` 开头的 base64 设备哈希会被 argparse 当作选项导致训练失败。新增 `src/utils/cli_args.py` 的 `normalize_option_value_args`，把 `--user -X` 规整为 `--user=-X`；训练子进程改用 `--users=<id>` 形式传参。四个 CLI（training / auth / policy-search / processing）均已接入。

## G. 本轮注意事项

- 旧 9 轴 checkpoint、scaler 与阈值不能继续作为线上模型使用；上线前必须重新生成 6 轴窗口数据、重新训练并重新运行 `policy_search`。
- 仅当 `auth.allow_training_fallback_policy = true` 时，缺少正式策略才允许以 `training_fallback_policy.json` 降级运行；默认 `false`，未完成 `policy_search` 的用户不会被接受进入认证。
- 认证结果字段已按尺度拆分，管理端 / App 端展示分数时应明确选择 `raw_*`、`ema_*` 或 `display_*`，不要把不同尺度混读。

# 2026-05-29 历史修改

> 以下为上一轮（2026-05-29）的修改说明，仅作历史记录保留。其中“VQGAN 9 轴输入”“`input_height == 9`”等描述已被 2026-06-29 本轮改动取代（现为 6 轴、`input_height == 6`）。

## 1. 修改目标覆盖

本轮修改围绕以下目标完成：

- 用户数据集生成从固定体量改为配置驱动的动态阈值，默认阈值 300MB。
- 数据切分按 75% / 12.5% / 12.5% 分配训练、验证、测试数据。
- 使用 HMOG 填充验证集和测试集时，让真实用户数据与 HMOG 数据量约为 1:1。
- HMOG 验证集使用排序靠前用户，测试集使用排序靠后用户，每侧至少 10 个用户，并以每个用户 24 个 session 为候选来源。
- 多用户数据处理从逐用户串行改为多进程并行；HMOG 加载也改为按 subject 并发加载。
- VQGAN 输入从旧 12 轴格式改为 `(1, 9, T)`，不再使用三个模长通道。
- 训练最大 epoch 改为 50，早停改为验证集性能连续 3 次不提升即停止。
- 训练、策略搜索和推理增加详细日志和结果字段，方便阈值与策略搜索。
- 保留 y-of-x 投票机制，新增并默认使用 EMA 决策策略。
- 将 `policy_search` 与线上认证策略打通，训练后默认写入线上消费的 `models/<user>/best_lock_policy.json`。
- 修复模型就绪检查遗漏 `processed_data/z-score/<user>/scaler.json` 的问题。
- 适配 Kunpeng 920 + Ascend 910B 8 卡 NPU 环境，并在多用户训练时利用可见 NPU 设备池。
- 将关键参数集中到 `ca_config.toml` 和 `deploy/config/ca_config.toml`，并补充中文注释。
- 补充项目文档、训练文档和本修改说明。
- 停止旧容器、删除旧服务镜像标签，重新构建并运行新镜像，完成健康检查和 NPU 可见性验证。

## 2. 数据集生成

配置入口：

- `ca_config.toml`
- `deploy/config/ca_config.toml`
- `src/ca_config.py`

核心实现：

- `src/processing/pipeline.py`

主要行为：

- `[processing].min_total_mb = 300`：默认触发阈值为 300MB。
- `[processing].target_total_mb = 300`：默认用于处理的数据目标为 300MB。
- `[processing].train_ratio = 0.75`
- `[processing].val_ratio = 0.125`
- `[processing].test_ratio = 0.125`

若系统设置阈值记为 `100x`，实际分配即为：

- 训练集：`75x`
- 验证集：`12.5x`
- 测试集：`12.5x`

HMOG 填充策略：

- 验证集使用排序靠前的 HMOG 用户。
- 测试集使用排序靠后的 HMOG 用户。
- 每侧默认至少 10 个 HMOG 用户。
- 每个 HMOG 用户默认以 24 个 session 为候选来源。
- `[processing].hmog_balance_ratio = 1.0`，即验证/测试集中真实用户数据与 HMOG 数据约为 1:1。
- `hmog_max_rows_per_subject` 和 `hmog_max_rows_total` 默认 0，生产运行不限制；smoke test 可临时设置上限以节省时间和磁盘。

并发改动：

- `process_all_users()` 使用 `ProcessPoolExecutor` 做用户级并行。
- 单个用户内部的 session 处理仍受 `[processing].workers` 控制。
- 多用户并发时会按用户级并发自动分配子任务 worker，避免所有用户同时抢满 CPU。
- HMOG subject 加载改为线程并发，避免每个目标用户串行重复加载同一批 HMOG。

## 7. 配置参数说明

`[processing]`：

- `min_total_mb`：触发预处理和训练的原始数据阈值，默认 300MB。
- `target_total_mb`：实际选择处理的数据量目标，默认 300MB。
- `train_ratio / val_ratio / test_ratio`：真实用户数据切分比例。
- `workers`：单用户内部处理 worker 数。
- `process_user_workers`：多用户处理并发数。
- `hmog_val_subject_count`：验证集使用的 HMOG 用户数。
- `hmog_test_subject_count`：测试集使用的 HMOG 用户数。
- `hmog_min_subject_count`：每侧 HMOG 用户数下限。
- `hmog_session_count`：每个 HMOG 用户候选 session 数，默认 24。
- `hmog_balance_ratio`：HMOG 与真实用户数据体量比例，默认 1.0。
- `hmog_max_rows_per_subject / hmog_max_rows_total`：HMOG 行数上限，默认 0 表示不限。

`[windows]`：

- `sizes`：窗口长度列表，当前默认 `[0.2]`。
- `overlap`：滑窗重叠率，默认 0.5。
- `sampling_rate_hz`：重采样频率，默认 100Hz。

`[auth]`：

- `max_decision_time_sec`：期望首次打断决策时间上限。
- `result_delay_sec`：认证结果发布延迟（秒），默认 `0`（每个数据包都回结果，兼容旧行为）。设为 `5` 表示累积约 5s≈50 个窗口后，按该用户策略（EMA / y-of-x）聚合再向 App 回一次包，发布间隔内的数据包只回 `Ack`；全量窗口仍逐窗落盘。折算窗口数 `target_windows = round(result_delay_sec / stride_sec)`，`stride_sec = window × (1 - overlap)`，实现见 `src/utils/reject_trackers.py` 的 `windows_for_delay` / `ResultEmitGate`。
- `decision_strategy`：`ema`、`vote` 或 `k`。
- `vote_window_size / vote_min_rejects`：y-of-x 投票参数。
- `ema_alpha`：EMA 默认平滑系数。
- `ema_alpha_candidates`：policy_search 的 EMA 候选值。
- `target_window_frr`：窗口级 FRR 约束。
- `max_genuine_first_interrupt_p`：真实用户在目标时间内被误打断概率约束，可选。
- `policy_search_auth_method`：默认 `vqgan-only`。

`[training]`：

- `max_epochs`：最大训练轮数，默认 50。
- `early_stop_patience`：早停耐心值，默认 3。
- `batch_size`：训练 batch size。
- `device`：默认 `auto`。
- `max_parallel_train`：最大并行训练任务/设备数，默认 8。
- `run_policy_search`：训练结束后是否自动运行策略搜索。

## 11. 注意事项

- 旧 12 轴 checkpoint 与旧阈值不能继续作为线上模型使用。
- 新用户或已有用户上线前必须重新训练并重新运行 `policy_search`。
- 若在非 Ascend 机器上运行，`device=auto` 会回退到 CUDA 或 CPU。
- 本轮用户数据烟测为了快速完成使用了较小数据阈值和 HMOG 行数上限，不能代表完整生产训练性能。
- 生产环境建议保留 `INSTALL_TORCH_NPU=1`，并确保宿主机 Ascend driver/toolkit 与容器挂载路径一致。
